# 抉择，抉择

群聊决策币插件，内含100+种回复模版。有概率出现：两者皆有可能，这就是答案

在两个或更多选项之间等权随机给出答案，可套用随机回复模板、调用当前会话模型生成 15 字以内的原因。复用 AstrBot 已配置的模型，无需单独填写 API Key 或安装额外 Python 依赖。

## 概率规则

每条有效请求独立抽取一次。“特殊答案概率”默认为 10%，可以设置为 0–100 的整数百分比。默认二选一时：

| 答案 | 概率 |
| --- | --- |
| A 的模板回复及可选原因 | 45% |
| B 的模板回复及可选原因 | 45% |
| 两者皆有可能，这就是答案 | 10% |

设特殊答案概率为 `p%`、有 `n` 个选项，则每个普通选项的概率为 `(100-p)/n %`。例如默认三选一 `A还是B还是C` 时，A/B/C 各 30%，特殊答案 10%；特殊概率设为 25% 时，三个选项各 25%。

设为 0% 时只在普通选项中等权选择；设为 100% 时始终发送特殊答案。特殊文案仍为 `两者皆有可能，这就是答案`，不随选项数量变化。越界整数限制到 0–100，非法类型回退到默认 10%。短时间内可能连续返回同一答案，单次抽取不会保证轮流或凑齐比例。

## 用法

### 直接提问

群聊中先 **@ 机器人**，或使用 AstrBot 配置的唤醒前缀，再发送下面的问句。二选一、多选一都支持。

**方式一：“还是”两边加空格**

```text
吃火锅 还是 吃烤肉
吃火锅 还是 吃烤肉 还是 吃面
```

**方式二：加上“帮我选”，空格可省略**

```text
帮我选，吃火锅还是吃烤肉。
帮我选，吃火锅还是吃烤肉还是吃面。
```

这一方式要求问句中同时出现“帮我选”和“还是”。“帮我选”及其相邻逗号、冒号不会计入选项。

| 问句 | 是否触发 |
| --- | --- |
| `吃火锅 还是 吃烤肉` | 是，“还是”前后都有空格 |
| `帮我选，吃火锅还是吃烤肉。` | 是，同时包含两个触发词 |
| `吃火锅还是吃烤肉` | 否，没有空格，也没有“帮我选” |
| `吃火锅 还是吃烤肉` | 否，只在一侧加了空格 |
| `帮我选，吃火锅` | 否，缺少“还是” |

以上示例均以机器人已被唤醒为前提。第一种方式要求普通空格，制表符或换行不能代替；自然问句不支持用 `|` 分隔。

### 使用命令

发送 `/抉择` 后接选项。“还是”两边可以不加空格，也可以改用 `|` 分隔。

| 场景 | 发送内容 |
| --- | --- |
| 二选一 | `/抉择 吃火锅还是吃烤肉` |
| 三选一 | `/抉择 吃火锅还是吃烤肉还是吃面` |
| 带问号的提问 | `/抉择 今天出门还是待在家？` |

**用 `|` 分隔多个选项：**

```text
/抉择 吃火锅 | 吃烤肉 | 吃面 | 吃披萨
```

如果选项本身包含“还是”，建议用 `|`，避免把一个选项拆成多个。若 AstrBot 配置了不同的命令前缀，请相应替换 `/`。

### 回复示例

例如发送：

```text
帮我选，吃火锅还是吃烤肉。
```

**选中“吃火锅”时，可能回复：**

```text
当然是选择 "吃火锅"
俺寻思"吃火锅"是对的。
因为暖和又热闹
```

第一行始终是选择结果；第二行是随机模板；第三行是模型生成的简短原因。模板也可能是 `显然"吃火锅"更好。` 等其他文案。

**抽中特殊答案时，回复：**

```text
两者皆有可能，这就是答案
```

默认同时发送内置图片，可在配置中关闭“发送图片”。特殊答案不追加模板或原因。

### 按开关调整回复

“使用模板回复”和“给出原因”独立控制。即使关闭原因，仍可保留随机模板：

| 使用模板回复 | 给出原因 | 普通选项输出 |
| --- | --- | --- |
| 开启 | 开启 | 选项答案 / 模板 / 原因，共三行 |
| 开启 | 关闭 | 选项答案 / 模板，共两行，不调用模型 |
| 关闭 | 开启 | 选项答案 / 原因，共两行 |
| 关闭 | 关闭 | 仅第一行选项答案，不调用模型 |

模板中的 `[x]` 会替换成带双引号的完整所选答案，可在配置中自定义模板。

### 补充说明

- **原因最多 15 字**，空格与标点也计入长度。原因不好想时，使用 `因为xx善`，例如 `因为吃火锅善`。
- 未配置模型、调用失败、等待超过 15 秒，或原因为空、过长、多行时，也使用上述兜底格式。选项过长时，仅截短兜底原因中的选项并加 `…`，选择结果和模板仍保留完整答案。
- 答案先随机选定，模型只负责解释，不改变结果。每次普通回答最多调用模型一次，不修改聊天历史、不调用工具；关闭原因后不调用模型。
- 每个选项必须非空。`/抉择 A还是还是C` 等空选项输入会返回用法提示；选项内的空格会保留，问题末尾的问号会去掉，自然问句末尾的句号等标点也会去掉。
- 无法解析的自然问句及框架已匹配的其他命令交回 AstrBot 原有流程。插件回答后停止该消息的后续处理，避免 LLM 再追加答案。

## 配置

在 AstrBot 插件管理页打开“抉择，抉择”的配置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 特殊答案概率（`special_probability`） | `10` | 0–100 的整数百分比，剩余概率平均分配给全部选项。 |
| 使用模板回复（`template_enabled`） | 开启 | 是否在选项答案后另起一行显示随机模板，与原因开关独立。 |
| 给出原因（`reason_enabled`） | 开启 | 普通选项回复后追加模型生成的原因；关闭后不调用模型，不影响模板开关。 |
| 回复模板（`reply_templates`） | 103 条内置模板 | 原来的两条及新增的 101 条，每项等概率随机选取。必须含 `[x]`；无有效模板时使用默认模板。 |
| 发送图片（`send_image`） | 开启 | 特殊答案附带图片；关闭后仅发送文字。 |

自定义模板示例：`我选[x]。`、`今日答案：[x]`。特殊答案固定为 `两者皆有可能，这就是答案`，不套用模板、不追加原因。

内置模板完整列表在 `_conf_schema.json` 的 `reply_templates.default` 中，可以在配置页增删修改。所有内置占位符均为 `"[x]"`；同一模板重复出现的占位符都替换成带双引号的同一个所选答案。自定义模板即使只写 `[x]`，回复时也会自动加双引号；已写 ASCII 或中文双引号时不重复叠加。

从旧版升级时，仍使用原始两条默认模板的配置会自动扩充到 103 条并保存；其他已有自定义列表保留。若要改用完整内置模板，可以清空自定义列表，运行时将使用 103 条内置模板。

图片为 `assets/both_possible.jpg`，随插件安装包一起提供，不依赖原始电脑上的图片路径。普通选项答案及用法提示不附图；若内置图片缺失或无法构建图片组件，退回纯文字并记录日志。

## 安装

GitHub 仓库：[zsmkmojang-a11y/astrbot_plugin_decision](https://github.com/zsmkmojang-a11y/astrbot_plugin_decision)。仓库已公开，可在 AstrBot 插件管理页通过此地址安装。

1. 将整个 `astrbot_plugin_decision` 文件夹复制到 AstrBot 的 `data/plugins/`。
2. 在 AstrBot 插件管理页重新加载插件，或重启 AstrBot。
3. 发送 `/抉择 吃火锅还是吃烤肉` 检查是否返回一个答案。

也可在支持本地 ZIP 安装的插件管理页上传交付的 `astrbot_plugin_decision-0.3.2.zip`。`metadata.yaml` 已设置上述仓库的更新地址。

原因生成使用 AstrBot `v4.5.7` 加入的当前会话模型查询和 `llm_generate` 接口。缺少该接口时仍能随机选择并给出兜底原因。

## 验证

在插件目录执行：

```console
python -B -m unittest discover -s tests -v
```

测试遍历各选项数量下全部等可能抽样值，验证默认二选一 45%/45%/10%、三选一 30%/30%/30%/10%、自定义概率及 0%/100% 边界；同时检查文本解析、命令用法、自然问句、命令冲突、模板和原因开关的四种组合、图片开关、当前会话模型接收全部选项、原因字数、异常回退及事件停止行为。AstrBot 接口和模型响应使用最小替身，未在真实 AstrBot 实例及消息平台联调。

安装后建议人工检查：二选一和多选一的命令、@ 后的 `A 还是 B` / `帮我选，A还是B。`、无空格的普通 `A还是B` 不触发、特殊概率 0% 与 100%、模板与原因开关的四种组合、普通未 @ 的群消息、特殊答案附图及关闭“发送图片”后仅发文字，以及回答后没有额外 LLM 回复。
